## 1. Contrato `Marketplace`

| Operación | Semántica |
|---|---|
| `createListing` | El vendedor deposita el activo en escrow (NFT/1155) con precio fijo en BRLT |
| `buy` | El comprador deposita el BRLT en escrow (estado `Funded`) |
| `confirmReceipt` | Libera el pago al vendedor y entrega el activo al comprador |
| `cancelListing` | Devuelve el activo al vendedor (solo antes de la compra) |
| `openDispute` | El comprador abre disputa tras pagar |
| `resolveDispute(releaseToSeller)` | El **árbitro** libera al vendedor o reembolsa al comprador |

- `ARBITER_ROLE` separado de `DEFAULT_ADMIN_ROLE`; `ReentrancyGuard` en todas las operaciones con fondos.
- `IERC1155Receiver` implementado (el escrow recibe lotes ERC-1155).
- **Compliance de activos:** se añade `setEscrowOperator` al admin del activo. La exención aplica solo a la
  **entrada** al escrow; la **entrega final al usuario** vuelve a exigir elegibilidad (test dedicado).

## 4. API de marketplace

| Endpoint | Función |
|---|---|
| `POST /api/listings` | Publica un activo (requiere **SOCIO**; precio > 0 y cantidad > 0) |
| `GET /api/listings` | Publicaciones activas con ISSUER y alias del vendedor |
| `POST /api/orders` | Compra con **doble escrow** (tx BRLT + tx activo obligatorias) |
| `GET /api/orders` | Órdenes del usuario (comprador y vendedor) |
| `POST /api/orders/{id}/confirm` | Solo el comprador; libera el pago (`settled`) |
| `POST /api/orders/{id}/dispute` | Solo el comprador, con motivo |
| `POST /api/orders/{id}/resolve` | Solo `arbiter`/`admin`: reembolso al comprador o liberación al vendedor |

- Estados gobernados por los triggers de v3 (`pending_payment → escrowed → confirmed/disputed → refunded`),
  con los **dos tramos del escrow** exigidos al confirmar.
- Reembolso registrado como pago `refund` al comprador (sin `order_id`, respetando `validate_payment_payee`).
