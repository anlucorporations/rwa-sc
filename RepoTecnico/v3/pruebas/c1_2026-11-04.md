| Comprobación | Resultado |
|---|---|
| `POST /api/claims` (multipart) | ✅ valida **magic bytes** (no `file.type`), tamaño ≤ 10 MB, `sha256`, **cifrado AES-256-GCM** y firma EIP-191 del solicitante |
| `GET /api/claims` | ✅ historial del titular con estado y programa |

| `GET /api/claims/{id}/typed-data` | ✅ EIP-712 del claim para firmar por el Emisor |
| `POST /api/claims/{id}/issue` | ✅ verifica firma EIP-712, exige **emisor autorizado del programa**, guarda `issuer_id`, `issuer_signature`, `tx_hash` y pasa a `approved` |
| `GET /api/claims/{id}/documents` | ✅ metadatos (solo titular/Operador/Admin) |
| `GET /api/documents/{id}` | ✅ descifra en servidor y sirve `Content-Disposition: attachment` + `nosniff` |
| RBAC de servidor | ✅ `requireAnyRole` valida `role_assignments` vigentes por petición |
| UI | ✅ `/identidad/claims` (solicitud + historial), `/emisor/verificacion` (Operador), `/emisor/solicitudes` (Emisor firma y emite) |
| **E2E real** (Next + PostgreSQL 16) | ✅ **16/16 PASS** |

**E2E (16/16):** sesiones SIWE de 3 roles · identidad · programa `kyc-base`/KYC · solicitud `pending` ·
usuario no verifica (403) · usuario no emite (403) · cola del Operador · verificación `documents_verified` ·
Operador no emite (403) · typed-data · **emisión firmada `approved`** · emisor y firma persistidos ·
usuario ve el certificado · metadatos del documento · **descarga descifrada idéntica al PDF original** ·
documento sin sesión 401.

> Transparencia: la consulta SQL posterior de evidencia no se pudo ejecutar (el entorno de prueba se
> limpió antes); las aserciones E2E cubren estado, emisor, firma y roundtrip de cifrado/descifrado.
