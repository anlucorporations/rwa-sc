[OBJETIVO]
disenar un metaplace de intercambio, compra y venta de Token bajo el sistema de RWA, esta plataforma certifica las identidades y ofrece una  metodologia para crear idendidad web 3, certificar estas identidades. contara con 3 instancias para cada tarea proporcionando soporte en los grandes pasos. la playtaforma usa barloToken (BRLT con 8 decimal) como moneda de pago de servicio, bienes, productos y NFTs.

[contexto]

1. la plataforma debe tener una estructura de METAPLACE e integra las 3 suites bajo el mismo concepto visual.
2. los mensajes de autorizacion/firma/nft enviados a la billetera deben ser entendibles por el usuario comun con un lenguaje amable y bien coloquial. se deben hacer mensajes plantillas para cada tipo de proceso que involucra la billetera



[procesos generales]

1. al inscribir al usuario por primera vez se deben obtener el claim (certificado) de Socio para acceder al Metaplace. Este certificado se obtiene al completar el proceso de KYC avanzado.
2. para tokenizer un activo real se debe contar con el certificado de Garantia y de fiador. se cargan todas las caracteristicas del activo real y los documentos en formatos PDF que avalan la tenencia del mismo.
3. para cada actividad de comercio se generaran ISSUES para que los usuarios puedan solicitar su certificados (claims).
4. la plataforma sirve de METAPLACE para los articulos Tokenizados (Productos elaborados, bienes o servicios). siempre que se cumpla las condiciones dedas en el ISSUSER.

[WEB-IDENTITY]

Esta seccion sirve para inscribir al usuario dentro del metaplace, la function principal es crear una identidad unica para usar sin comprometer los datos de su billetera dentro de la plataforma, normalmente se concideraria una Suite de Usuario donde se ancargaran de gestionar las solicitudes de certificaciones (claims) para poder operar en las diferentes secciones del metaplace.

[WEB-ISSUSER]

esta seccion es la suite de Aministrador. aqui se crean los ISSUSER que clasifican las distentas actividades de intercambio, Tambien se aprueban las certificaciones solicitadas por el usuario, se monitorea toda la plataforma desde la seccion Sistema, se custodian los procesos de recuperacion de identidad, Etc. a esta Suite solo pueden acceder dos tipos de usuario: Administrador que tiene acceso a todas las funciones administrativas y de certificacion de la plataforma, y el Operador que solo tiene acceso a la verificacion de documentos en los procesos de solicitud de una certificacion.
los ISUSER se crean definiendo el proceso y los requisitos que debe cumplir el usuario (documentos en formato PDF/PNG u otras certificaciones previas), los ISSUSER pueden contener vario certifidacos. Tambien alberga el proceso de Tokenizacion de: 
1. Productos: se acunan las cantidades finales de un producto elaborado, prreferiblemente productos artesanalaes.
2. Servicios: se acunan las cantidades por servicio ofrecido; se estima 60 servicios por mes. el valor del token por servicio se expresa en BRLT (evalua la posibilidad que sean NFT que se queman al uso).
3. Bienes: se acuna un NFT por el bien a vender.

[WEB-TOKEN]

esta seccion es el METAPLACE para la compra/venta/intercambio de los token creados, NTFs y criptomonedas (solo simbolico sin valor real).
